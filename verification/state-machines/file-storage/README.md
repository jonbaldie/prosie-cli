# File storage models

Inventory S19 and S20 at `3dd1171b29bd4dccc8c4e995438f658f18b818b1`. These finite models do not prove the Go implementation or filesystem.

## Source mapping and scope

S19: `internal/config/config.go` and `internal/filewrite/replace.go`, both `resolveLinks`: `Inspect` models Lstat, `ReadLink` models a successful read and abstract path transformation, and `ReadError` models Readlink failure. Lstat and Readlink errors can happen at later hops. Missing, non-link, cycles, 1/39/40-link relative, absolute and mixed chains are represented; the 40th target is not inspected. There is no visited set. `RelativeTarget` checks the relative-base class, not full pathname correctness. Path values are symbolic classes, not actual names: mixed links choose a relative or absolute target class on each hop and the carrier records the last choice. This preserves link kind and budget, but abstracts away individual identities, directory changes and pure pathname transformation; it does not prove correctness for arbitrary strings or actual mixed-chain bases. Filewrite may fail at Stat before reaching its resolver. The config source mutant and direct test cover the config copy; filewrite also has a direct resolver budget test.

S20: `internal/filewrite/replace.go` `Replace`, `resolveLinks`, `replaceRegular`, `writeAndSync`: `Stat`, `Direct`, `Resolve`, `Create`, `Chmod`, `Write`, `Sync`, `Close`, `Rename` and `Cleanup` represent the corresponding calls. Resolution and target identity are abstracted to an unresolved/resolved class. Requested mode is an input; existing regular mode overrides it. Temp existence, bytes, actual mode, successful write/sync/close flags, result, publication and published mode are carried separately. Successful creation gives the temp private mode 0600. `SelectedMode` is the requested or existing mode. Successful chmod installs it; failed chmod permits the private mode to remain or the selected mode to have been installed. Other partial permission outcomes are outside these finite OS outcome classes. A failed cleanup retains the modeled actual temp mode, not an assumed successful chmod. A full byte count with a write error is represented by `tempBytes = "new"` and `writeOK = FALSE`; partial or empty writes fail. Stat, resolve and create errors set failure; close is attempted after chmod/write/sync failure. Direct writes to special files are in-place and a partial result fails. The deferred Remove may fail and leave the temp behind; no cleanup guarantee is claimed.

`PreserveMode` checks regular-file mode on success. `PublishedAfterSuccess` checks that regular/missing publication requires a complete nonfailed write, successful sync and close, and no earlier failure; before publication the old modeled bytes remain. Missing paths use an old-content sentinel, not a claim that they contain a file. The direct special-file branch is outside this property. The actual code preserves permission bits, not other inode metadata. Error classes and finite byte/mode classes are abstractions, not proofs for arbitrary inputs. No concurrency, hostile paths, crash durability or directory-sync guarantee is claimed; filesystem call behavior and same-directory rename semantics are assumptions. S18 credential publication has its own model.

## Evidence and replay

From the repository root run `python3 verification/state-machines/verify.py file-storage --self-test`. The runner checks real Go tests and both TLC models, then executes matched source/model mutants and repeats baselines:

- Relative base: `TestFormalStorageRelativeLink` calls the real config resolver; the source and model mutants use the wrong base.
- Mode: `TestFormalStorageReplaceMode` calls real Replace through a symlink and observes bytes, mode and retained link; mutants discard the old mode.
- Publication: the existing `TestFailedExportKeepsPreviousFile` runs the real CLI in subprocesses with a file-size limit. Its source overlay bypasses the write/close error guard before rename; the model mutant makes the same guard bypass. Its test requires the error and unchanged old bytes. The manifest requires the top-level PASS/FAIL markers, so a platform where the build-tagged test is absent or skipped cannot count as a catch. This test uses Linux or Darwin and depends on RLIMIT_FSIZE. It does not separately inject a close or sync error.

Both packages' `TestFormalStorageLinkBudget` exercise 39 and 40 links. `TestFormalStorageRenameFailureCleansTemp` exercises one real cleanup success; it does not prove cleanup cannot fail. These are supporting checks, not separate mutant-backed properties.

Read every result with /statechart by name, `Links.tla` and `Replace.tla`, with their cfg and `view.mjs`. Use `Links-chart.cfg` for a smaller link chart; the full bound is 40 traversals and one replacement. The statechart does not replace inspection of the real-code evidence.
