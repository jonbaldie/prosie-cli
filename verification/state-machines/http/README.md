# HTTP and relation lookup: S16, S17

## Properties and harm

- `BodyClosed`: an ordinary response owned by `readResponse` is closed before it returns, on success or error. A leak can exhaust connections.
- `BookSurvives`: a failed secondary chapter lookup does not discard a successfully decoded book. Otherwise the user loses access to a book when only its chapters are unavailable.

These are bounded model checks, not proofs of the Go implementation. The Go tests exercise actual methods through an in-memory HTTP transport. They check ordinary response closure, stream ownership, a failed chapter lookup, a partial chapter read, and series lookup and order. They do not cover every failure or endpoint.

## Mapping and boundaries

S16: `internal/client/client.go` `NewRequest`, `newRequest`, `Do`, and `CheckResponse`; `internal/client/response.go` `request`, `readResponse`, and `execute`; `internal/client/generate.go` `openSSEStream`. `BuildFailure` combines request construction and transport failures; `Receive` is successful transport; `OrdinaryReturn` combines status checking, optional reading, and deferred close. Close is visible at function return, not atomic with the earlier reads. `StreamReceive`, `StreamReject`, `StreamAccept`, and `StreamClose` describe rejected and accepted stream ownership; the stream branch is not covered by `BodyClosed`. `execute` has a separate close site and is not covered by the real-source mutant. Model return errors include read errors, but there is no retry or remote rollback model. The model does not assert close success: the code ignores close errors.

S17: `internal/client/books.go` `GetBook` and `bookChapters` map to `PrimaryBook`, `RelationPresent`, `Lookup`, and `LookupReturn`. A primary failure follows `BuildFailure`. Secondary transport, status, and decoding failures are abstracted as unavailable. A read error can still yield decodable bytes: it is not necessarily unavailable. The test uses a transport failure. `internal/client/series.go` `ListSeries`, `GetSeries`, `populateSeriesBooks`, `newSeriesBookIndex`, and `members`, and `internal/client/books.go` `ListBooks`, map to `PrimarySeries`, `SeriesBooks`, and `SeriesCodex`; each lookup stage also represents a skipped lookup. Series list has no codex request; its second stage is skipped. Those stages in `HTTP.tla` model only the best-effort shape. See `Flows.tla` for the refined observations.

Each execution chooses one finite flow. There is one primary response and at most one abstract lookup per stage. No time, concurrency, transport internals, retry, server consistency, or remote side effects are modeled. In particular a failed read or decode does not undo a server mutation. The action that returns a book abstracts its Go statements; no other actor observes intermediate local assignments. The stream caller's eventual close is an external modeled action, not a liveness guarantee. The model cannot establish that caller executes it.

## Refined flow model

`Flows.tla` separates marshal, request construction, transport, status, raw read, endpoint decode, status-only execution, and stream body transfer. A rejected stream is closed by the helper; an accepted stream stays open until `CallerClose`. `StreamRejectClosed` checks the rejected case, and `leak-rejected-stream` pairs it with an actual Go defect. The real test observes that an accepted body remains open, the transport receives the unique caller context, and the original client's positive timeout is unchanged. Under Go's HTTP client timeout behavior, that context identity would differ if the client imposed its positive timeout; the test observes removal for this request, not elapsed timing or a clone field. A separate test calls `StreamContinue` and observes its deferred close after parsing.

For hydration, `Primary`, `Relations`, `Chapters`, `Books`, and `Codex` show primary failure, present or empty relations, ignored secondary failure, decodable bytes after a chapter read error, one book lookup for a list, and independent codex resolution for a single series. The finite classes use either empty StoryIDs or `<<2, 1>>`. With explicit IDs, members are ordered subsets in StoryIDs order. With empty IDs, members are ordered subsets of the two-book index order `<<1, 2>>`, selected by matching SeriesID. This is an algorithm boundary, not a proof of indexing or normalization. `TestFormalHTTPPartialChapterRead`, `TestFormalHTTPSeriesBestEffort`, and `TestFormalHTTPListSeriesIndexOrder` exercise actual client methods. Only the three named invariants are checked guarantees; the other states are observations.

The primary action is an atomic S16 request and decode outcome; there is no composed proof. Secondary failures, including cancellation, are grouped as unavailable because they have the same future best-effort behavior. A chapter partial read that decodes is a separate success class. The list has one symbolic series; codex presence is independent of book presence. Original and per-request timeout classes are separate: only a positive stream timeout is removed, and a later request observes the unchanged original class. The caller context identity is retained; cancellation is an external transport outcome or stream parse return, not a promise of network or server rollback. The timeout model uses classes, not durations, and does not prove timing. Arbitrary JSON values, backend effects and the full index algorithm are outside the model. `flows-view.mjs` is the view for `Flows.tla`; `view.mjs` is for `HTTP.tla`.

## Replay and mutation

From the repository root run `python3 verification/state-machines/verify.py http --self-test`. The runner checks the Go tests and TLC baseline, applies scratch Go overlays and matching model edits, requires the named failures, and reruns baseline. `leak-response` removes the `readResponse` defer and breaks `BodyClosed`; `discard-book-on-secondary-failure` returns an error after an empty chapter lookup and breaks `BookSurvives`. Read EVERY model result with /statechart. A failing real test is evidence about the tested Go path; a TLC failure is a counterexample to the model, not by itself evidence of a production defect. Compare both paths to source before drawing a conclusion.
