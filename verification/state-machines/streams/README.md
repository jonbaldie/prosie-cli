# Stream models

S14 and S15 model `internal/client/stream.go`. These are bounded models, not proofs of Go execution or the server.

## S14: frames

`eventFrame.accept` maps event lines to `EventLine`, data lines to `DataLine`, ignored lines to `OtherLine`, and blanks to `Separator`. Event names replace earlier names; data lines append to a sequence. The sequence represents the newline-joined callback argument. `eventFrame.dispatch` emits the pair and resets both fields. `readEvents` maps EOF to `End`, `EmptyEnd`, or `BlankEnd` and non-EOF error to `ReadError`, which does not process the partial line or dispatch the pending frame. `EmptyEnd` models an empty EOF read: `accept("")` dispatches once and the EOF branch dispatches the now-empty frame again. `BlankEnd` models a CR-only unterminated final line: trimming makes it blank, so acceptance dispatches the pending frame and EOF dispatches an empty frame. `End` models flushing an unterminated nonblank final line, abstracting acceptance of that line as the preceding line action. `lineMode` distinguishes a terminated line from an unterminated final line; no further lines can follow the latter. Frame input is at most three lines, event names empty/x/y and data values empty/a/b. String prefix recognition, trimming and join formatting are symbolic; actual multiline formatting is checked by Go. `FlushAtEOF` checks both the expected dispatch count at EOF and the last emitted frame. Losing it can lose a result or token. The model holds callback and reset in one action.

## S15: results

`streamEvents.accept` maps error, valid done, nonempty delta, invalid/empty done and other events to named actions. `done` retains the last decoded value, with `zero` including JSON null for the tested struct; invalid and empty JSON retain the prior value. Callbacks can follow error or done. `End` models EOF/read-error and the context state when `readEvents` returns. `Return` models `streamSSE` selecting context error, read error, retained stream error, missing completion, or the last done value in that order. `ErrorRetained` prevents a later done from erasing an error. `ReturnPrecedence` checks the full selection order. A wrong order can hide cancellation or another earlier-priority error. Each callback is atomic; up to three events occur. Delta parsing and non-nil callbacks are represented by `DeltaEvent`; empty, malformed and nil-callback deltas have the same retained state as `OtherEvent`. Error text and JSON values other than zero/one/two are abstract. `InvalidDone` coalesces malformed and empty inputs because their future effects match. Other modelled behavior is observational, not a separately asserted guarantee.

## Evidence and limits

Run `python3 verification/state-machines/verify.py streams --self-test` from the root. The runner executes actual `TestFormalStreamsFrame` and `TestFormalStreamsResult`, checks both models and each real-source and model defect, and repeats the baseline. `lose-final-frame` removes EOF dispatch; `done-clears-error` loses an error; `read-before-context` reverses the first two return checks. The latter tests a cancelled context and a real reader error together. The single precedence mutant demonstrates that ordering pair; the other precedence clauses do not each have an independent source defect. Go tests also check multiline and empty data, repeated and empty event names, CR-only final lines, late callbacks, last done, null and empty done. The model treats the Go reader, callbacks and JSON decoding as sequential and assumes no concurrent mutation. It does not prove liveness, arbitrary lengths, network behavior or server persistence. Read every result with `/statechart` using `view.mjs`; use `Frame-chart.cfg` for a complete two-line chart because the three-line baseline exceeds the chart budget.
